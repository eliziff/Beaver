# Improvements found during the consolidation, held for later

The consolidation keeps the parse output byte-identical (DOC off and on, every split, against the baseline dumps in
`F:\fable-doc\base`). Anything found along the way that would change a byte is written here instead of being done, with
where it is, what it would change, and how it was found. Each is its own piece of work, measured when taken up.

| # | Where | What it would change | Found |
|---|-------|----------------------|-------|
| 1 | `transition/lines.rs` `unmarked_notes` | The mark recovery for a note label with no body mark lives in the line table DOC reads, not in the one note pairer (`note_pairing::pair_notes`); moving it there would give t0's output the recovered marks too. | 2026-11-07, footnote-links work |
| 3 | `transition/lines.rs` `LineTable::plain` (t0) and `LineTable::read` (DOC's walk) | Two readings of each line's markers and reference marks: DOC's reads the recognizer's likely misreadings (the confusion table) and recovers unmarked note marks, t0's reads neither. One line table for both tiers would change t0's readings or DOC's inputs. | 2026-11-07, consolidation unit 1 |
| 4 | `transition/doc.rs` `read_in`, `Move.rank`; `decide/write.rs` `write_lines` | DOC's reading order (LEGALPDF_TRANSITION_DOC_ORDER=on, and the DOC oracle's gold ranks) sets each line's `Move.rank`, which only the old separate emit path wrote to the page (`reading_order = rank`, d754d8d); since c98205f no writer reads it, so the setting changes nothing. The one writer taking a move's rank would bring the reading order back as output (changes DOC-order output only; default output unchanged). | 2026-11-07, consolidation unit 3 |
| 5 | `transition/doc.rs` (DOC with `export9`) | DOC's output differs between two runs of one binary on the same documents: 12 of 1,124 test parses (30 of 9,950 development) came out otherwise on a second run of the baseline grader (nodes' extents, roles, continuations). Byte identity with DOC on is therefore checked against a second baseline run. Making DOC's reading the same every run (its ONNX sessions' threads, or an order read off a hash map) would fix those parses' output to one of their readings. | 2026-11-07, consolidation units 1-2 check |
| 6 | `transition/emit.rs` `structure_graph` (`assemble_parents`, then `graph/outline.rs` `assemble_outline`) | Two parent rules on one parse: the engine's (`legal-structure` `hierarchy::assemble`, no translation-column or quotation contexts) gives each node its first parent and a provision its section path alias ("12(1)(a)"); tier 0's outline then sets the parents the output keeps. One rule (the engine's taking the outline's contexts) would make the aliases follow the kept parents, so a provision's alias could change where the two rules part. | 2026-11-07, consolidation unit 4 |
| 7 | `legal-pdf-evidence` `opening_marker`, `legal-pdf-machine` `lines::line_readings` | Two readings of a line's opening marker by the numbering grammar: evidence's reads the first token against the families the lines before it opened (`&mut families`, state carried line to line) into one `Marker`; the machine's reads every reading of the line, its variants, its text before the repair and its likely misreadings, with no such context. One list read once with `opening_marker` its first (plan unit 8) would change a line's marker wherever the families' context picks another reading than the first. | 2026-11-07, plan unit 8 |
| 2 | `legal-citations` `reference_names::reference_name_ends` | It runs a full citation `extract` over a whole source decision (all jurisdictions) to collect statute titles; a Canadian-only pass is 2.3x faster on 40 decisions but finds one more statute on one of them ("Employment Insurance Act (Can.), ss. 22 and 23"), so links could change. | 2026-11-07, quote-check profile |
