# OCR candidate screen

A bounded recognition experiment for [Indra's Latin recognizer](https://github.com/datalab-to/indra),
[PP-OCRv6 Tiny](https://huggingface.co/PaddlePaddle/PP-OCRv6_tiny_rec_safetensors),
and [OpenOCR RepSVTR mobile](https://github.com/Topdu/OpenOCR), extended with
[docTR MobileNetV3-Small CRNN](https://mindee.github.io/doctr/using_doctr/using_models.html).
Training uses the existing Kraken Arrow line crops
without duplicating the page corpus. Source lists retain the original article
partition; the harness rejects page or article overlap.

The delivered runtime is now the five-tier Indra package in
[Legal Browser OCR v0.2.3](https://github.com/eliziff/legal-browser-ocr/releases/tag/v0.2.3).
Production browser and native consumers use that shared model manifest. Earlier
Kraken comparisons and intermediate candidates below remain experiment history.
The native runtime remains v0.2.2; v0.2.3 changes the browser pipeline only.

checks the extracted package, its inventory, overwrite protection and all five
tiers against the independently invented fixture generated by
`authorities_lite_ocr.mjs HTML OUTPUT`.

`release_benchmark.mjs MANIFEST OUTPUT TIER:cpu|webgpu|auto,... 3 QUERY`
measures the real browser document action with the frozen PDF, three warm passes,
first-document and initialization timings, human CER and searchable-PDF gates.
It renders its PNG smoke input from that PDF instead of requiring the desktop's

of `3`; keep its sample count separate from candidate medians. The laptop and
desktop follow-up receipts live in private `browser/full-test/latest/*/runtime-speed/`.
`tensorWidth=64` or `128` tests tensor padding; original line widths stay unchanged.
These experiments did not improve the laptop result. The 8-pixel default remains.

The v0.2.3 browser defaults overlap a real PDF.js worker, CPU detection/crop
preparation and one GPU recognizer, using two bounded ordered page batches.
`prepareWorker=0`, `fixedBatch=0`, `pdfPort=0`, and
`layoutBackend=webgpu&layoutWorkers=1` are ablation controls. Final results live
under `runtime-speed/v023-final/`; the laptop also runs hosted PNG recognition
and model switching through all five tiers. `OCR_BENCH_SKIP_HOSTED=1` skips that
additional smoke during a timing sweep; the receipt records the skip.

The following scripts produce separate experimental artifacts rather than
changing the released weights or dependencies:

  placement, not a throughput benchmark. HardSwish was already decomposed by

  runtime remains the pinned custom 1.22 build. The slower JSPI candidate was
  rejected as a laptop default.

Speed-oriented training should select a cheaper inference setup against an
accuracy floor on development pages: lower-width recognition, lower detector
resolution, a smaller distilled student, or an INT8 variant. Ordinary continued
training leaves the inference graph's cost largely unchanged. Human transcripts
directly supervise lower-width recognizer training. Kraken boxes can provide
weak detector supervision, but matching them is not evidence of improved
detection. Corrected boxes or independent transcript-based evaluation are needed
to support that claim. Keep the frozen article/page split, measure actual browser
latency, and use test pages only after selecting settings on development.

The longer run is limited to Indra and CRNN, the two candidates that beat the
installed Kraken's measured CPU throughput. Select `--models indra crnn` and
use `--warm-start` pointing to the initial screen's output root, with
`--output benchmarks/local-data/ocr-candidate-screen/convergence`. This keeps
the one-epoch checkpoints and receipts intact. Existing weights and appended
character rows are retained. The initial checkpoints did not contain optimizer
state, so the first continuation uses fresh AdamW moments.

Each epoch scores the unchanged development split. The learning rate halves
after three consecutive epochs without an absolute CER improvement exceeding
0.00001, down to 0.000001. Stop after eight epochs without that improvement,
with at least ten total epochs and a thirty-epoch cap. Any lower development
CER can still select the best checkpoint; the threshold controls patience.
Test results never select checkpoints or learning rates. The test partition
was already examined in the smoke test, so this is a follow-up on the existing
test set rather than a newly untouched benchmark.

`best.pt` holds selected weights; `last.pt` additionally holds optimizer,
scheduler, RNG state and the epoch history. Both are written atomically.
After an interruption, rerun the same command with `--resume`; completed models
are skipped and a partially trained model resumes from its last full epoch.
Use `evaluate.py --models indra crnn` with the convergence output root only
after training and checkpoint selection finish.

`paired_timing.py` compares the two selected exports with Kraken after a full
warmup pass, rotating the starting model across three trials on the same frozen
512-line sample. Pass `--data-root`, `--crnn-weights`, the convergence `--output`,
`--kraken-pack` and `--kraken-runtime`. It writes `paired-timing.json` without
repeating accuracy evaluation. Use its internally matched ratios when desktop

Indra's public release has no trainer. `indra.py` reconstructs its fused
convolutional graph from the actual ONNX initializers; three independent ONNX
comparisons must reproduce IDs and lengths exactly, with confidence tolerance,
before training. Its model licence still applies to derived weights.

PP-OCRv6 uses its installed Transformers implementation. RepSVTR uses the
upstream OpenOCR checkout and checkpoint. The harness bypasses their
inference-only softmax for CTC loss and checks that the resulting probabilities
match their public forward methods. Missing training characters are appended
to the pretrained classifier; existing character indices are preserved.
RepSVTR's unused auxiliary GTC checkpoint heads are excluded, and its encoder's
gradient-detaching guide option is disabled for full fine-tuning. Final export
uses the upstream RepViT fusion procedure, with a numerical parity check.

The fourth candidate uses `python-doctr==1.1.0` in the existing training

shapes, and scores the full test split on CPU. Pass the same asset/output
arguments plus `--kraken-pack` and `--kraken-runtime`. CPU timing is the median
of three runs on a frozen 512-line ordinal sample, batch size 16 and two ONNX
threads. It times warm inference on prepared tensors, not complete pages.
To evaluate only the fourth candidate, also pass `--models crnn`,
`--crnn-weights` and `--receipt crnn-evaluation.json`; the initial three-model

`audit_repsvtr.py` compares the actual upstream `RecDynamicResize` evaluator
against the controlled line preprocessor on 256 development lines, using stock
and trained weights on GPU. It takes `--data-root`, `--openocr`, `--rep-weights`

`optimize_repsvtr.py` takes those same arguments. It calibrates only on 64
uniformly spaced training crops, then compares FP32, dynamic MatMul INT8, full
signed/unsigned QDQ INT8 for convolutions and matrix multiplications, and signed
convolution-only QDQ. Development CER and
median timing select the fastest export within +0.05 percentage points CER of
FP32. The final reserved-test score is computed only for the selected model;
identical completed test receipts can be reused by model and corpus hashes.
`--resume` reuses completed development scores after checking artifact hashes.
The installed ONNX Runtime's `CalibMaxIntermediateOutputs` option drops
unaggregated ranges, so it is deliberately omitted. Original exports remain
intact; quantization-input graphs are disposable and removed in `finally`.
