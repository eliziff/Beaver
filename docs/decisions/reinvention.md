## 6. Priority ranking — the five costliest REINVENTED/PARTIAL rows

Ordered by correctness risk first, duplicated maintenance second.

### 1. Cited-scope-first quote resolution is missing entirely (`a2aj_pinpoint_scope.py` → nothing)

**Cost: correctness, and it is a product-level gap, not a code-quality one.** The fork can locate a quote in a document (`sourceDoc.ts:666`) and can resolve a locator to a block (`:340`), but it cannot do the thing the reference spent 43 tests on: search the *author's own pinpoint first*, and when the quote is not there, say so with a graded verdict instead of silently reporting a match found somewhere else in the document. `resolve_quote`'s taxonomy (`a2aj_pinpoint_scope.py:524-578`) is the difference between "verified" and "the quote exists but the pinpoint is wrong" — the single most common real defect in legal writing.

**Remediation:** port `cited_scopes` (`:244`), `structure_blocks` (`:314`), `cited_blocks` (`:371`), and `resolve_quote` (`:477`) onto the existing `SourceDoc` block model, keeping the four hard-won guards: section-ancestor climbing (`:334-340`, so `s 34(2)(e)` matches a `s 34` block), synthetic combined-range blocks with real-block precedence (`:437-466`, `:499-520`), the sub-3-word document-uniqueness guard (`:551-561`), and abbreviated-range expansion (`:114-123`). **Differential:** AST-harvest the 43 `test_a2aj_pinpoint_scope.py` cases into `benchmarks/grammar_vectors/` (the harvester at `benchmarks/grammar_vectors/harvest.py` already does exactly this for the splitter) and run them as a vitest suite, exactly like `legal-pdf-parser/tests/test_oracle_vectors.py:45-60`.

### 2. One oracle function, two divergent fork statute spines (`a2aj_structure.section_structure` → `statuteSpine.ts` + `sourceDocA2AJ.sectionSpine`)

**Cost: correctness (inconsistent answers) plus duplicated maintenance.** `statuteSpine.ts:102-198` is attributed and gated but **drops** the hyphen/mixed hypotheses and **adds** `dotterm`. `sourceDocA2AJ.ts:616-702` is unattributed and ungated but **keeps** hyphen/mixed with `requireRoot` (`:661-665`) and has no `dotterm`. Both descend from `a2aj_structure.py:191-270`. Consequence today: the same statute text resolves a **different section spine** depending on arrival path — Library documents go `legalTextSkeleton.ts:37,223` → `computeStatuteSpine`, A2AJ documents go `a2ajLocalBulk.ts` → `compileA2AJSourceDoc` → `sectionSpine`. Locators, pinpoint URLs, and retrieval handles all key off that spine.

**Remediation:** merge into one exported function — statuteSpine's `dotterm` style plus sourceDocA2AJ's hyphen/mixed + `allows_hyphenated_provisions` gate (`a2aj_structure.py:187-188`, present in the fork only as the inline `/\brules?\b/iu` at `sourceDocA2AJ.ts:705`) — and route both callers through it. **Differential:** re-run the existing gate (`backend/scripts/skeleton-oracle-probe.py` → `skeleton-oracle-diff.ts`) on the merged implementation and require it to hold the current published numbers (431 texts / 24 datasets; 296/296 exact, 100% label recall — `__tests__/statuteSpine.test.ts:5-8`, `__tests__/legalTextSkeleton.test.ts:226-228`), then extend the probe to dump A2AJ *case* texts so the paragraph and page spines get the same treatment.

### 3. A2AJ response caching threw away the domain insight (`a2aj_client.py:203-271` → `a2aj.ts:355-411`)

**Cost: correctness under provider failure, plus needless load.** ALR caches a decided case's text **permanently** because a decided case never changes (`a2aj_client.py:223-226`), keeps a **negative cache** for empty 200s (`:256-258`), and on any request failure returns the **last known good** response (`:260-265,269-270`) — three behaviors with three named tests (`tests/test_a2aj_client.py:332-441`). The fork re-derived a cache with mtime TTLs of 30 d / 24 h (`a2aj.ts:39-42,365-368`), no negative cache, and no stale fallback, so an A2AJ outage becomes a user-visible failure and repeated misses re-hit the API forever. Notably the fork **did** consciously preserve cache-*key* parity with the Python side (`a2aj.ts:319-328`) — the key was audited, the policy was not.

**Remediation:** make `requestCacheTtl` (`a2aj.ts:365`) tier on `docType` (`cases` → no expiry), add a negative-cache marker file, and add stale-on-failure to `readPersistentResponse` (`:371`). **Differential:** port the three named ALR tests verbatim as vitest cases against `a2aj.ts`.

### 4. The UK/US public-source providers were rebuilt from scratch (`case_url_providers/*` → `publicLegalSources.ts`)

**Cost: duplicated maintenance and a lost refusal contract.** `publicLegalSources.ts` independently reimplements the TNA Atom search, the GOV.UK ET search (including the same title-must-contain-the-case-number confirmation, `:656-657`), and the GovInfo search with the same `DEMO_KEY` fallback (`:769`) — same origins, same endpoints, no attribution, no header docstring. 13 reference tests (`tests/test_uk_case_url_providers.py` 8, `tests/test_us_case_url_providers.py` 5) encode the discipline that matters for these providers: **return nothing rather than a plausible-but-ambiguous URL**, and fail closed on network error. Whether the TS versions honor it is untested. Separately, `case_url_providers/composite.py`'s ordering, negative memoization, exception isolation, env kill switch, and host allow-list have no counterpart at all — the fork re-queries known misses and has no off-ramp for a misbehaving provider short of a deploy.

**Remediation:** harvest the 13 provider tests into `benchmarks/grammar_vectors/` and run them against `searchTnaCase` / `searchGovUkEtCase` / `searchGovInfoCase` with a stubbed fetch; fix whatever they catch. Then port `CompositeCitationDatabase` (`composite.py:23-129`, ~130 lines) as the dispatcher behind `lookupPublicLegalSource` (`publicLegalSources.ts:872`), bringing the negative memo and the `ALR_CASE_URL_PROVIDERS`-style kill switch with it.

### 5. Two corpus indexes over one corpus, and a hardcoded overlay filename (`local_a2aj.py` index/manifest → `import_a2aj_bulk.py` + `sweep.py`)

**Cost: duplicated maintenance and a silent-breakage path.** ALR already builds a revision-guarded exact-lookup index over the corpus (`lookup.duckdb`, `local_a2aj.py:615-689`, schema `"5"` + revision check `:625-635`) keyed by the very normalizer the fork ported. The fork builds a **second** index (`citation_lookup` in `a2aj.sqlite`, `import_a2aj_bulk.py:45-49`) over the same bytes with the same keys, and no fork code ever opens `lookup.duckdb` (it appears only in comments and in the test-time oracle probe). Meanwhile the corpus is read three inconsistent ways: `build_citator_graph.py:384-388` reads `manifest.json` for the family list but never re-verifies sha256; `sweep.py` never opens the manifest at all; and `sweep.py:33-35` **hardcodes** `public_endpoint-424c9f516423.db` — a content-hash filename produced by `overlay_store.py:178`, which changes on any reference DB rebuild, silently breaking the sweep.

**Remediation:** three concrete steps. (a) Decide and document whether `a2aj.sqlite` must exist alongside `lookup.duckdb` — if yes, say why in `import_a2aj_bulk.py`'s docstring; if no, read the existing index. (b) Add manifest sha256/revision verification to every fork corpus reader (a shared helper ported from `local_a2aj._file_matches:809-817` and the `_ensure_lookup_index:615-635` revision guard), so a half-installed or superseded snapshot fails loudly rather than producing quietly wrong numbers. (c) Replace hardcoded overlay filenames with a glob-plus-manifest resolution, and move Beaver's own artifacts (`citator\noteup.sqlite`, `build_citator_graph.py:18`) out of ALR's private data directory into `OPEN_LEGAL_DATA_HOME`. Also port `_parquet_equivalent` (`local_a2aj.py:827-853`) so a row-reordered-but-identical parquet does not force a full re-import.

## 7. Things this audit found that were not expected

1. **The known-row claim about `sourceDocA2AJ` was backwards.** The task expected `sourceDocA2AJ.ts` to be the earlier conscious port of `a2aj_structure.py`. It is not: `sourceDocA2AJ.ts` cites nothing (grep for `a2aj_structure|ALR|Quote Verifier|ported` over the file returns only substring false positives — `already`, `reported`), while `statuteSpine.ts:1-16` and `retrievalGate.ts:19` carry the attribution. Yet `sourceDocA2AJ.ts` is **the more faithful port of the two** — its `paragraphBlocks:434-504`, `pageBlocks:514-594`, `sectionSpine:616-702`, and `flatSectionBlocks:704-729` reproduce `a2aj_structure.py:76-117`, `:128-184`, `:191-270`, and `:282-341` gate-for-gate and constant-for-constant, including the `bounded = out[:-1] or out` median trick and the leading-child regex. It is a **hidden port**: fully derived, entirely unattributed, entirely ungated. That is worse than a reinvention, because nobody knows to re-diff it when the oracle moves.
2. **One concrete behavioral drift, in exactly the case its own comment names.** `sourceDocA2AJ.ts:413-417` breaks candidate ties by candidates-array order; `a2aj_structure.py:52` breaks them by lowest scope index (`min(candidates, key=lambda i: (scopes[i][0][1], i))`). They diverge when two scopes share a first marker number — i.e. a decision whose table of contents repeats paragraph numbers, which is precisely the scenario `sourceDocA2AJ.ts:396-400` says the function exists to handle.
3. **The citator does not duplicate ALR — ALR has no citator.** A repo-wide grep of ALR's Python for `noteup|citator|note_up|note-up` returns zero hits. The 2.1 GB `citator\noteup.sqlite` in ALR's data directory is a **Beaver** product (`build_citator_graph.py:18`).
