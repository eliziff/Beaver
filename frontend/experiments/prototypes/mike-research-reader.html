Executive readout

Make the model decide. Make code remember and prove.

Beaver can become faster and cheaper without asking a smaller model to remember less accurately. The safe move is to remove mechanical work from the model, preserve exact legal state outside prose, and retrieve only the evidence needed for the current question.

7.6k Approximate fixed prompt/tool tokens

Current cloud legal-research turns pay this before history, retrieved text, attachments, or the new user request.

75k Possible tokens in one flat Library read

A 300,000-character document response can dominate the entire turn when a paragraph or footnote lookup would suffice.

3 Memory forms, not one summary

Exact state, a disposable narrative summary, and a recent verbatim tail serve different purposes and should stay separate.

Current conclusion: the largest strict wins are structural retrieval, deterministic citations and links, durable state, and bounded document edits. Generic prose compaction comes after those foundations and must pass legal-fidelity benchmarks.

Work allocation

What should stop consuming model reasoning

“Deterministic” means the same validated input produces the same result, with an audit trail and no model guess where exact code can do the job.

01 Implemented

Verified pinpoint links

A2AJ and public-source quotes are checked against source blocks. Beaver builds native anchors or multi-text fragments after the model responds—even when citation JSON is omitted.

02 Implemented

Bounded DOCX citation linking

The assistant calls one job. Deterministic code splits where it can, resolves providers, builds links, and applies OOXML changes; a bounded model handles only genuinely ambiguous splits.

03 Implemented

Durable local chats and shared data

Account-free chats now use validated, atomic files under shared local AppData. Library and legal caches use the shared legal-data root while cloud/Supabase paths remain available.

04 Strict next win

One structural artifact per document version

Hash each PDF/DOCX once, retain pages, sections, paragraphs and footnotes, and reopen the artifact on later lookups instead of flattening the whole file again.

05 Strict next win

Opaque evidence handles

Let the model cite a short handle. The server owns numbering, quote verification, source identity, locator choice, final URL, storage, and cross-chat isolation.

06 Strict next win

Persistent provider locator sidecars

Store source ID, kind, label, parent, offsets, aliases and native anchor beside each bulk snapshot. Avoid rebuilding structure into process-only maps after every restart.

07 Strict next win

Version-bound find and replace

Return an opaque match ID from search; let code apply one, repeated, or all replacements and return changed excerpts. Full-document rereads become explicit verification, not ritual.

08 Strict next win

Bounded spreadsheet operations

Read an A1 range and patch explicit cells against an expected workbook version. Preserve untouched package state or reject unsupported features rather than regenerate a workbook.

09 Strict next win

Native Word references and templates

Bookmarks, REF, PAGEREF, SEQ and tagged template fields let Word maintain numbering and repeated facts. Models choose semantic values; deterministic code owns OOXML.

10 Benchmark first

Tool-group routing and compact history

Expose only relevant stable capability groups and replace old prose with a state capsule plus summary. Both can hide needed information if recall is not measured, so neither ships blind.

Durable legal research

A legal test is a graph, not a model-drawn picture

The durable object stores doctrine, assertions, exact passages, provenance and review state. Layout is a disposable view that code can reproduce.

Repository decision: start with MIT-licensed @xyflow/react and @dagrejs/dagre, lazy-loaded on the graph route. Keep the versioned legal JSON independent of either renderer. This is researched and designed; the Beaver runtime viewer is still an implementation item.

Commentary

Journal analysis stays identifiable as secondary material.

Each spoke holds source ID and revision, locator hierarchy, exact text and hash, authority metadata, review state, and a deterministic public/local link. For example: 2002 SCC 86, para. 64. The model requests evidence; it never constructs this URL.

Legal memory

Compaction should not be the source of truth

Current Beaver still sends the whole visible conversation on each turn. Codex is also launched as a fresh ephemeral thread, so its native cross-turn memory and compaction are discarded.

Raw transcript

Immutable audit record. Never deleted by compaction.

durable
Exact state capsule

User constraints and supersession; document/version hashes; evidence IDs, quotes and locators; edits; workflow state.

authoritative
Narrative summary

Rationale, exploration and conversational history. Useful but replaceable; never relied on for exact legal facts.

lossy
Recent exact tail

The newest turns remain verbatim so tone, local references and unresolved reasoning survive the checkpoint boundary.

bounded
Targeted retrieval

Rehydrate only the exact cases, statutes, paragraphs, document ranges or spreadsheet cells needed by the current turn.

on demand
Legal advantage: citations, propositions, quote spans, pinpoints, source revisions, document versions and accepted edits already have natural structured identities. Beaver can compact surrounding prose aggressively while retaining those objects exactly.

Automatic policy

Trigger on projected need, not a magic percentage

Codex derives an automatic threshold near 90% of context. OpenCode uses context limit minus the larger of output allowance and a reserve. Beaver should use the reserve-based approach because legal tools can return large evidence blocks mid-turn.

compact when estimated next request > context window − max(output allowance, legal-tool reserve)
Level 0 · always Keep exact receipts

Replace repeated payload copies with source IDs, hashes, ranges, truncation flags and cursors. Preserve raw data in storage.

Level 1 · soft pressure Drop old bulk

Remove old reasoning and large tool outputs from the model view. Keep exact calls, outcomes and re-fetch handles.

Level 2 · projected overflow Create checkpoint

Reduce older dialogue to a narrative summary while retaining the exact state capsule and recent verbatim tail.

Level 3 · recovery Native compact or rebuild

Use a provider checkpoint when compatible. If it fails, rebuild from raw history, exact state and the recent tail.

Exact state that must never be left only in a summary
User instructions and which instruction supersedes which; client facts with provenance; jurisdiction and time cutoff; document IDs, versions and hashes; accepted/rejected edits; canonical source IDs; verbatim quote text and its hash; paragraph, section, subsection, subparagraph, page and footnote locators; proposition-to-authority links; workflow phase and unresolved questions.

External comparison

What a Harvey comparison can honestly mean

We cannot presently make a direct “Beaver versus Harvey” claim.

Harvey’s published 2026 model scores use a private holdout that mirrors its public Legal Agent Benchmark, and its Arena uses internal tasks and lawyer preference votes. Those numbers are not directly comparable to a run on the public task set.

  • Run Beaver in the public Harvey LAB harness at a pinned commit.
  • Preserve the harness action space, task files, rubrics and all-pass grader; record any adapter differences.
  • Compare Beaver memory arms to each other directly. Treat Harvey’s published holdout results only as contextual evidence.
  • If Harvey later publishes matching public-run product outputs or grants evaluation access, run blind pairwise review on the same tasks and source snapshot.

Output directive

Caveman is a benchmark arm, not a default

The repository’s own documentation says the skill reduces output, not input or reasoning, adds roughly 1–1.5k input tokens per turn, and can become net-negative on already-terse work.

Legal warning:

The stock directive says to drop hedging. In law, qualifications, exceptions, uncertainty, jurisdiction limits and standards of review are often substantive—not filler. An omitted qualifier can leave a short answer technically wrong or professionally unsafe.

Test verbatim

Repository Caveman lite

Use the published “lite” level, not full or ultra, as one reproducible arm. Measure realized whole-turn cost and rubric completeness, not the repository’s output-only percentage.

Legal-safe candidate

Concise legal drafting directive

Remove pleasantries, repetition and process narration while expressly preserving legal qualifications, exact quotes, citations, defined terms, requested format and audit-relevant explanation.

Independent Caveman acceptance criteria
It wins only if total priced tokens and latency fall, every mandatory rubric element survives, citation and quote fidelity do not regress, legal qualifications are not omitted, and blind reviewers do not prefer the control. Evaluate response-text entailment and omission categories in addition to exact-answer accuracy.
